# Data provenance, licensing and AI-generated content

This repository commits a prepared corpus and a set of relevance judgments so that the sample runs
without a generation step and so that everyone measures the same thing. Both contain material that
needs disclosure, and the data is **not** under the same licence as the code.

### Why the data is different

The corpus derives from **[goodbooks-10k](https://github.com/zygmuntz/goodbooks-10k)** by Zygmunt
Zając, which is licensed
**[Creative Commons Attribution-ShareAlike 4.0 International](https://creativecommons.org/licenses/by-sa/4.0/)**.

CC BY-SA is a *share-alike* licence. Work derived from it must carry attribution and be shared under
the same terms. The files in `data/` that carry book titles, authors, publication years, ratings and
tag-derived genres are derivatives of that dataset, so they are offered under CC BY-SA 4.0 and not
under this repository's MIT licence.

The original CSVs are **not** redistributed here — `data/raw/` is git-ignored and
`dataprep download` fetches them from the upstream repository on demand.

**If you are reusing this data, attribute goodbooks-10k and preserve CC BY-SA 4.0.** If you are
folding this sample into another repository, have the licensing reviewed; mixed-licence repositories
need the boundary stated explicitly, which is the purpose of this file.

## AI-generated content

Two of the committed artifacts were produced by large language models. Neither is a human-authored
or authoritative source, and both are included because reproducibility requires everyone to measure
against identical inputs.

### Book descriptions — `data/books.blurbs.json`, and the `blurb` field of `data/books.enriched.json`

**These are not real publisher blurbs, dust-jacket copy, or reviews.** They are approximately
120-word descriptions generated by a large language model from each book's title, author, publication
year and genre labels.

They are **synthetic text about real books** and should be treated accordingly:

- They may contain factual errors about plot, characters, themes or publication history.
- They are not endorsed by, affiliated with, or derived from any author or publisher.
- They must not be presented as descriptions of the actual works, quoted as such, or used to inform
  any judgement about the real books.

They exist because goodbooks-10k ships no description field, and a corpus of titles and author names
alone is too thin to demonstrate anything meaningful about text relevance or vector similarity. Any
sufficiently descriptive text would serve; the specific content is incidental to what is being
measured.

One title, `book-7372`, was replaced during generation because the model's content filter refused
the original prompt. The replacement is a public-domain work chosen to be uncontroversial. See
[`docs/decisions.md`](docs/decisions.md).

### Relevance judgments — `data/judgments.json`, `data/judgments.second-judge.json`

**These are model-generated relevance grades, not human relevance judgments.** Each is a 0–3 grade
for one (query, document) pair, produced by prompting a language model.

Standard information-retrieval benchmarks such as TREC use trained human assessors. This sample does
not, and that is a genuine methodological limitation which is stated in
[`docs/report.md`](docs/report.md) section 9 rather than hidden.

What has been done to make them defensible:

- The pool was graded **twice, by two different models**, and every published conclusion was
  recomputed against both. Agreement was substantial (quadratically weighted Cohen's κ = 0.735) and
  26 of 27 conclusions were identical. The one that changed is flagged where it appears.
- The judge was **blind to which retrieval strategy produced a document** — it sees only the query
  and the document.
- Both judgment sets are committed, so anyone can recompute every number, or substitute their own
  judgments and see what changes.

The residual limitation is real and unresolved: both judges come from the same model family, so a
bias shared across that family would be invisible to this check.

## Reproducing the data

Every committed artifact can be rebuilt. `data/corpus-manifest.json` records the generating model,
embedding model, dimensions and vector encoding so that provenance is discoverable from the data
itself.

```powershell
dotnet run --project src/CrossIndexQuery.DataPrep -- download          # fetch goodbooks-10k CSVs
dotnet run --project src/CrossIndexQuery.DataPrep -- prepare           # join, resolve genres
dotnet run --project src/CrossIndexQuery.DataPrep -- blurbs submit     # generate descriptions
dotnet run --project src/CrossIndexQuery.DataPrep -- blurbs collect
dotnet run --project src/CrossIndexQuery.DataPrep -- embed             # vectors + manifest
dotnet run --project src/CrossIndexQuery.DataPrep -- stats             # corpus statistics sidecar
dotnet run --project src/CrossIndexQuery.DataPrep -- judge submit      # relevance judgments
dotnet run --project src/CrossIndexQuery.DataPrep -- judge collect
```

Regenerating the descriptions or the judgments produces **different text and different grades**, so
published numbers are only comparable against the committed artifacts. The embedding vectors, by
contrast, are deterministic and are treated as a rebuildable cache rather than as source data.
